# 全員掲載ランキング（2026-10-16、公開準備）

> 状態メモ（2026-10-20）: 機能自体は現行アプリに実装済み。この文書は公開範囲と配備順の詳細資料として残す。現在構造は `feature-map.md`、公開可能なフィールドと権限は `firestore.rules` を優先する。

ユーザーの明示依頼により、非表示・参加ボタンを廃止し、許可・メール確認済みユーザー全員が閲覧できるランキングへ変更する。掲載するのは表示名・写真・問題集1/2の合計回答数/正解数/正答率/連続正解/連続使用/XPだけ。メールや問題ごとの回答・学習計画・詳細JSONは一般ユーザーに共有しない。

自分の成績は保存成功後にleaderboard/{uid}へ自動反映。過去のleaderboardVisible設定は参照しない。管理者がランキングを開く/更新すると、登録済みusersのうち許可メールでアクセス停止されていない人の集計をまとめて反映し、対象外の公開行を削除する。これにより既存ユーザー本人のアプリ更新を待たずに一覧へ反映できる。管理者以外はusers一覧・アクセス管理一覧を取得できない。

アクセス管理・自己停止禁止・本の進捗・個人の学習記録を維持。停止ユーザーはランキングの取得・掲載も拒否され、管理者の停止操作で公開行も削除する。

## 必要な手操作（1回）

1. Firebase Consoleのcbtpass-a680e → Firestore → ルールで現在のルールを控える。
2. **このブランチの最新firestore.rules全文**へ置き換えて公開。過去の参加設定付きルールや管理者専用ルールを使わない。accessControl/users制限は保持され、leaderboardだけが一般利用者向けに追加される。
3. ルール公開完了を伝える。テスト済みアプリをPagesへ公開する。
4. 公開後は新しいURLの版指定リンクから開き、表示版10/16-4を確認。管理者がランキングを開けば既存登録者の集計が作成される。

この環境にはFirebase本番の配備権限がない。本番ルールの反映と実アカウントの確認はローカルエミュレータの検証とは別。

## 更新の改善

古いタブを開いたままでは配備後も古い画面が動き続ける。sw.jsの更新時に古いHTMLのキャッシュを更新し、オンラインの画面読み込みはHTTPキャッシュより新しいHTMLを優先する。問題画像の保存とオフライン時のHTMLフォールバックは保持。開きっぱなしの旧タブは新しい版指定URLで開き直す。
