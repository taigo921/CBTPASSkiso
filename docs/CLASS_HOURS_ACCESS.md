# 授業時間の利用制限（公開前の確認用）

管理者（メール確認済みの `itaigo921@gmail.com`）以外は、月〜金の以下の時間帯に利用できません。日本時間で、開始を含み終了を含みません。

|授業|制限時間|
|---|---|
|1|08:40〜10:10|
|2|10:25〜11:55|
|3|12:55〜14:25|
|4|14:40〜16:10|

休み時間・昼休み・放課後・土日・日本の祝日・登録した休校日は利用できます。授業中の画面には既存の泣いているGIFを全面表示し、「授業中のため利用を制限しています」と終了時刻を重ねます。休み時間には自動で解除し、GIFの読み込みも止めます。個別のアクセス停止とは別の制限で、授業時間のためにGIFを出したり、個別停止を解除したりしません。

## 管理者の操作

ホーム → 「ユーザーのアクセス管理」 → 「授業中の利用制限」。制限全体のオン／オフと、日付指定での休校日の追加・解除ができます。これらの操作は画面・API・Firestoreルールで管理者に限定します。早く授業が終わった場合は「この授業の制限を解除」を1回押すと、その日の現在の授業だけ全員に開放します。次の授業では自動で制限を再開し、翌日には持ち越しません。個別のアクセス停止は解除しません。休み時間・休校日・全体解除中・既に解除済みの場合はボタンを無効にします。設定の受信には通信が必要です。休校日は366件までです。土曜授業の指定・特別な短縮時間割は今回の対象に含みません。

祝日は内閣府の[国民の祝日CSV](https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv)（2026-10-18取得）から2026・2027年を収録しました。振替休日・国民の休日を含みます。2028年以降の祝日表はクライアントとルールの両方の更新が必要です。

## 保存と制限の範囲

学習データの内容・保存形式を変更せず、削除・リセットしません。起動時から授業中なら個人の進捗取得を待ち、休み時間にログイン処理を再開します。起動済みなら画面を覆って操作を止め、通常問題の回答タイマーも一時停止します。模試の試験時間は従来の実時間方式です。休み時間には同期購読・保存を再試行します。学習済みの途中回答は端末に残ります。通信不良や保存容量不足の場合、既存の保存警告・バックアップ機能が適用されます。

Firebaseは `request.time` を日本時間に換算し、授業中の一般ユーザーによる `/users/{uid}` の読み書きとランキングの読み書きを拒否します。端末時計を変えてもサーバーの制限は回避できません。クライアントの画面切替は端末時計で1秒ごとと画面復帰時に確認します。

GitHub Pagesは公開された静的アプリです。旧版・改変されたアプリ、ダウンロード済み教材そのものを遠隔消去したり、時計を改変したオフライン端末で教材閲覧を完全に防ぐことはできません。新しい制限画面を適用するにはアプリ更新が必要です。

## 公開手順

この変更はアクセス制御に関わるため、AGENTS.mdに従い実装・テスト済みのPRへの承認後に公開します。PagesだけではFirebaseルールは更新されません。

1. PRの具体的な動作・影響を確認し、公開を承認する。
2. Firebaseコンソール → CBT PASSプロジェクト → Firestore → ルールに、このPRの `firestore.rules` **全文**を貼り付ける。末尾の閉じ括弧までコピーする。既存のアクセス管理・ランキングルールを残した統合版です。
3. ルールを公開する。この環境にはFirebaseの本番デプロイ権限がないため、この1操作は管理者による手動実行が必要です。設定文書がない場合は制限オン・休校日なしが既定です。ルール公開からアプリ更新までの間、旧版は授業中の同期が拒否される場合があるため、休み時間か放課後に行ってください。
4. Firebaseルールの公開が確認できたらPRをマージする。既存の必須テストを通った場合だけPagesが公開する。
5. 配信されたHTML・SW・引き継ぎ書をコミットと照合する。管理者と一般ユーザーの実機で、休校日登録→反映、授業中→休み時間の解除、同期再開を確認する。
