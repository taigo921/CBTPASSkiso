# 管理者のアクセス停止・解除

未公開の準備版。ホームの「ユーザーのアクセス管理」で登録済みユーザーの名前とメールアドレスを表示し、各行の「アクセス停止」「アクセス解除」を切り替える。メール確認済みの itaigo921@gmail.com 専用。管理者自身は操作できない。

## 保存と制限

- `accessControl/{Firebase Auth UID}` に `blocked`、`updatedBy`、サーバー時刻の `updatedAt` を保存。学習記録とは別で、進捗同期やバックアップによって停止状態が上書きされない。
- 一般ユーザーは自分の停止状態だけを取得できる。停止中も状態の受信は許可するが、本人の `/users` データの読み書きは禁止。管理者は一覧を取得でき、他人の停止状態のみ変更可能。
- 新版アプリは起動時にサーバー確認が成功するまで開かない。接続できないときはキャッシュの許可状態では開かないため、**オフラインでの新規起動はできなくなる**。
- 起動中は停止状態を購読し、停止通知時に画面を閉じ、ユーザー情報・表示中の管理者一覧をクリアし、問題タイマーを停止する。再接続・画面復帰時にもサーバー確認する。保存済みの学習記録は削除しない。
- UID単位の利用停止であり、Firebase Authアカウント自体の無効化・トークン取り消しではない。管理者API・秘密鍵は使用しない。アカウント削除後に新UIDで再登録するケースまでメールアドレス単位で永久追放する機能は対象外。
- GitHub Pages上の問題JSON・画像は公開配信であり、この機能でURL自体を非公開にはできない。旧版やオフライン端末の保存済み問題まで遠隔で利用不能にはできない。Firestoreへのオンラインアクセスは新版を開いていなくてもルールで拒否する。

## 公開に必要な手順

この環境にFirebase管理用の接続はなく、実プロジェクトのルール更新は未実施。

1. [Firebase Console の Firestoreルール](https://console.firebase.google.com/project/cbtpass-a680e/firestore/rules) を開き、既存ルールを手元に控える。
2. このPRの `firestore.rules` を確認して反映し「公開」。最新ルールは全員掲載ランキングとアクセス管理を統合した版。アクセス管理は本人専用の制限を保持する。過去の管理者専用/参加設定付きランキングルールを使わない。
3. ルール反映完了と、この認証変更（オフライン起動の制限を含む）の公開承認を伝える。
4. Codex側でテスト済みPRをマージし、テスト付きPages公開と本番ファイル一致を確認する。先にHTMLだけ公開するとaccessControlへの読み取りが拒否され全員がログインできなくなるため、順序を逆にしない。
5. 管理者でログインし、許可ユーザーの協力のもとで停止→別端末の画面ロック→解除→再ログインを確認する。本番の実ユーザーはテストのために勝手に停止しない。
